## 1. Nuestro compromiso

Como integrantes del equipo de desarrollo de **CirculApp**, nos comprometemos a mantener un entorno de trabajo respetuoso, profesional y colaborativo.

El objetivo es que todas las personas puedan participar en el proyecto, aportar ideas, realizar consultas, proponer cambios y expresar desacuerdos de manera constructiva.

Este código se aplica a las interacciones realizadas dentro del repositorio, Issues, Pull Requests, Projects, documentación y demás espacios relacionados con el desarrollo del proyecto.

## 2. Comportamientos esperados

Se espera que todos los integrantes:

* Mantengan una comunicación respetuosa y profesional.
* Escuchen y consideren las opiniones de los demás.
* Realicen críticas sobre el código y no sobre la persona.
* Fundamenten las propuestas y decisiones técnicas.
* Acepten correcciones y sugerencias de otros integrantes.
* Colaboren en la resolución de problemas.
* Informen cuando una tarea presente dificultades o bloqueos.
* Respeten las responsabilidades asignadas.
* Cumplan los acuerdos establecidos por el equipo.
* Mantengan actualizada la información de sus tareas.
* Utilicen correctamente Issues, Pull Requests y el Project.
* Soliciten ayuda cuando sea necesario.
* Reconozcan los aportes realizados por otros integrantes.

## 3. Comunicación y revisión de código

Las revisiones de código tienen como objetivo mejorar la calidad del proyecto y detectar posibles problemas antes de integrar los cambios.

Durante una revisión:

* Los comentarios deben estar relacionados con el código o la tarea.
* Las observaciones deben ser claras y fundamentadas.
* No se deben realizar comentarios ofensivos o personales.
* Las diferencias técnicas deben resolverse mediante argumentos y evidencia.
* Se debe evitar interpretar una observación técnica como una crítica personal.
* Los integrantes deben estar abiertos a modificar sus propuestas cuando exista una razón técnica válida.

Una revisión de código debe buscar mejorar el resultado del proyecto, no señalar errores personales.

## 4. Comportamientos no aceptados

No se permiten:

* Insultos, amenazas o ataques personales.
* Acoso o intimidación.
* Comentarios discriminatorios.
* Burlas dirigidas a otros integrantes.
* Descalificaciones personales relacionadas con el nivel de conocimiento.
* Publicación de información personal o privada sin autorización.
* Uso deliberado de lenguaje ofensivo en Issues, Pull Requests o documentación.
* Conflictos personales trasladados al repositorio.
* Modificaciones intencionales que perjudiquen el trabajo de otros integrantes.
* Eliminación o alteración deliberada de trabajo ajeno sin justificación.
* Uso de credenciales, tokens o información sensible de otros integrantes.

## 5. Resolución de desacuerdos

Los desacuerdos técnicos forman parte del desarrollo de software y deben resolverse de manera profesional.

Cuando exista una diferencia de criterio:

1. Explicar claramente la propuesta.
2. Fundamentar la decisión con argumentos técnicos.
3. Escuchar la propuesta alternativa.
4. Evaluar las ventajas y desventajas de cada opción.
5. Buscar una solución consensuada.
6. Si no se alcanza un acuerdo, recurrir al responsable correspondiente del proyecto.

Las decisiones deben tomarse priorizando las necesidades del proyecto y no las preferencias personales.

## 6. Responsabilidad sobre el trabajo

Cada integrante es responsable de mantener informado al equipo sobre el estado de sus tareas.

Si una persona encuentra un bloqueo que le impide continuar, debe comunicarlo lo antes posible mediante los canales definidos por el equipo.

También se espera que cada integrante:

* Mantenga actualizado el estado de sus Issues.
* Informe cambios relevantes.
* Respete los plazos acordados.
* Solicite asistencia cuando una tarea exceda sus conocimientos o recursos disponibles.
* Evite ocultar errores que puedan afectar al resto del equipo.

Comunicar un problema a tiempo es preferible a intentar ocultarlo o continuar sin informar al equipo.

## 7. Uso responsable del repositorio

Todos los integrantes deben contribuir a mantener el repositorio organizado.

Se debe:

* Respetar la estrategia de ramas definida.
* Utilizar Issues para registrar tareas y problemas.
* Utilizar Pull Requests para revisar cambios.
* Respetar las convenciones de commits.
* Evitar subir información sensible.
* Evitar modificar trabajo ajeno sin coordinación.
* Mantener la documentación actualizada.
* Respetar las políticas establecidas en `CONTRIBUTING.md`.

## 8. Uso de herramientas de inteligencia artificial

Las herramientas de inteligencia artificial pueden utilizarse como apoyo durante el desarrollo cuando el equipo lo considere apropiado.

Sin embargo, cada integrante es responsable del código que incorpora al proyecto.

Antes de utilizar código generado o sugerido por una herramienta de inteligencia artificial, se debe:

* Comprender qué hace el código.
* Verificar que sea correcto.
* Revisar posibles errores.
* Comprobar que sea compatible con el proyecto.
* Verificar que no introduzca vulnerabilidades.
* Adaptarlo a las convenciones del repositorio cuando sea necesario.

El uso de herramientas de IA no elimina la responsabilidad del integrante sobre los cambios realizados.

## 9. Confidencialidad y seguridad

No se debe compartir públicamente información sensible relacionada con el proyecto.

Esto incluye:

* Contraseñas.
* Tokens.
* Claves API.
* Credenciales.
* Secretos de autenticación.
* Datos personales.
* Información privada de usuarios.
* Configuraciones sensibles.

Si se detecta accidentalmente información sensible en el repositorio, se debe informar inmediatamente al responsable correspondiente y proceder a su eliminación siguiendo el procedimiento establecido.

## 10. Aplicación del Código de Conducta

Todos los integrantes del equipo son responsables de respetar este código.

Cuando se produzca un incumplimiento, se debe informar al responsable del proyecto para evaluar la situación y determinar las acciones correspondientes.

Dependiendo de la situación, pueden aplicarse medidas como:

* Solicitud de modificación o eliminación de contenido inapropiado.
* Advertencia al integrante involucrado.
* Revisión de permisos dentro del repositorio.
* Mediación entre los integrantes.
* Comunicación con el responsable académico del proyecto cuando corresponda.

Las medidas deben ser proporcionales a la situación y buscar resolver el conflicto de manera objetiva.

## 11. Alcance

Este Código de Conducta se aplica a:

* Repositorio de Backend.
* Repositorio de Frontend.
* GitHub Issues.
* Pull Requests.
* GitHub Projects.
* Wiki.
* Documentación del proyecto.
* Reuniones relacionadas con el proyecto.
* Canales de comunicación utilizados para el desarrollo.

## 12. Reconocimiento

Este documento establece las normas internas de colaboración del equipo de desarrollo de **CirculApp** y complementa las reglas técnicas definidas en `CONTRIBUTING.md`.

El cumplimiento de estas normas permite mantener un entorno de trabajo organizado, respetuoso y orientado al desarrollo colaborativo.
